## Goal
Place the expiring catalogue and each proposal against the market on price and richness, and list what is missing.

## Starting point: the SME Benchmarking Tool (PBM)
- Market plans arrive as `SME-INTAKE v2.4` intake files (one per plan). Write ONE catalogue spec / intake adapter that
  reads that template into MARKET catalogues (rates by network × age band × member type × gender, levers, add-ons), so
  every shipped or future intake file loads without code changes.
- Reconcile its taxonomy with ours: levers → `registry/benefits.json` codes + factor families (`family_map`), add-ons →
  module families, its networks CN/GN/RN/RN2/RN3/VN → a canonical tier ladder through `tier_map.csv`.
- Its reference lever basis is a SYNTHETIC placeholder: load it as `benefit_factors.json` library entries only via a run
  input, flagged as placeholder; do not commit its values as a calibrated library.
- Reuse, don't re-implement, where the tool already answers a question (peer sets, DHA minimum test, NAS industry BC):
  WS2 compares on the workbench's canonical basis and reconciles to the tool's 5_Report on its own subject plan.
- Data boundary: NAS industry BC and the shipped intake files stay out of this repo (runs/ or the PBM clone only);
  fixtures for WS2 are fictional intake files generated by a builder here.

## Deliverables
1. Market catalogue intake through catalogue specs (kind `MARKET`); no new parser code per market source.
2. Tier matching across catalogues with different plan counts via `tier_map.csv` (SPEC §3.3; many-to-one / one-to-many with weights).
3. Value map: price (standard cell set and exposure mix) vs richness index per plan/tier; Parquet + Excel view.
4. Gap register: benefit lines present / absent / weaker vs market, by plan tier (SPEC §4.1 comparison rules).
5. Benefit taxonomy reconciliation with the owner's benchmarking tool (mapping table, not code).
6. CLI `benchmark`; end-to-end check added to `tools/laptop_check.py`.

- Market-facing outputs never name the incumbent reinsurer.
- Full suite green; `LAPTOP CHECK PASS` on the owner's laptop (SPEC §13).
