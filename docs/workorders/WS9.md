# Work order WS9 — Spec Builder workbook: author `template_spec.json` in Excel

Branch: `ws9-spec-builder` · Read: SPEC §8.0, §8.1, §8.4, §8.5, §8.6 (new), §13; `pw/template/spec.py` (schema
docstring, `cedant_model`); `pw/tender_kit.py`; docs/cedant_workbook_guide.md · Depends on: WS5 (cedant sections),
WS8 (tender folder and step files) · CR #26

## Goal
Today a tender's `template_spec.json` is hand-written JSON (the UFIC spec is ~36 KB). Other GC users are not
comfortable with JSON or Python. Give them an Excel **Spec Builder** workbook with dropdowns and fillable cells,
generated by the tool, filled by the user, and read back by the tool into `template_spec.json`. Owner decisions
(26 Oct 2026):
1. The builder covers **both** the reinsurer-template sections and the cedant-workbook sections.
2. Every field is entered as **structured rows**; no raw-JSON cells (formula, splits, sections, rows, refer cells
   included). `formula.refer_rules` is not carried until it has a real use.
3. **JSON is the master.** The builder is an editing view; the run, the manifest and every other tool keep reading
   `template_spec.json` only.
4. **No preview** output (no HTML, no summary workbook) in this work order.

## Deliverables
1. **`pw/template/builder.py`** (one module, both directions):
   - `generate_builder(spec | None, out_xlsx)`: a blank builder, or one pre-filled from an existing spec
     (age bands from `age_bands_file` resolved and shown). xlsxwriter, deterministic.
   - `read_builder(xlsx, base_spec=None) -> (spec, report)`: openpyxl; long tables read by header scan (spare and
     inserted rows read, as in `pw/template/cedant.py`); gated (below); on any problem no spec is written, the
     report lists sheet / cell / problem, exit code 2.
2. **Builder layout** (SPEC §8.6 is the contract; column order may be refined, sheet roles may not):

   | Sheet | Rows / content | Maps to |
   |---|---|---|
   | Cover | Steps, builder version, source spec hash, last-read status, fields not carried | — |
   | Tender | Label / value cells: cedant, tender_id, currency, premium_basis, deadline, issue_date, contact; reference_sheets (existing_rates, factor_tables, tob_summary, terms Y/N; addons READ_ONLY/FILL); options (allow_proposed_multipliers, allow_benefit_comments, protect_structure, language, rounding, outlier_shading) | top level, `reference_sheets`, `options` |
   | Lists | User-extendable lists for registry dimensions whose values are `dynamic` (TPAs, rating regions, networks) | dropdown sources only |
   | Age bands | band_set, order, label, age from, age to (blank = open top band) | `age_band_sets` |
   | Columns | column_set, column order, column label, key order, gender, marital, member_category | `column_sets` |
   | Sheets | sheet order, sheet_name, title, product_type, regulator, rating_region, mandatory, age band set **or** "sections" **or** "custom rows", column_set, co-pay basis (one column per family used), refer_text, premium_basis (if different), scope_id; formula: order, rounding, min_premium, max_premium (blank = default) | `sheets[]` |
   | Blocks & plans | One row per sheet × TPA block: block_id, tpa, label, comment, marital split Y/N, member-section split Y/N, band set / column set overrides; then one cell per plan letter (A, B, …) holding the network label (blank = not offered); plan label and plan_number derived as in the UFIC spec unless overridden on the Plan labels table below the grid | `blocks[]`, `plans[]`, `splits` |
   | Sections | scope (sheet, block, or sheet `split:member_section`), order, label, member_category, band set | `sections`, `split_options.member_section` |
   | Custom rows | block, row order, row label, section label, member_category, age from, age to; lines with the same block + row label form one row with several keys | block `rows` |
   | Refer cells | block, plan, gender, marital, member_category, age from, age to (blank = any) | block `refer_cells` |
   | Factors | sheet, component_id, family, key_dim, TPAs, key value, option, reference Y | `factor_tables` (+ `key_values`, `reference`, `tpas`) |
   | Riders | sheet, component_id, family (module_*), key_dim, TPAs, key value, option, unit, mode (ADD / MULTIPLY), eligibility, key label | `riders` |
   | Plan defaults | sheet, family | `plan_defaults` |
   | Benefits | sheet, benefit_code, plans (blank = all) | `benefits` |
   | Cedant workbook | catalogue_id, version, effective_date, spare_rows, notes (one per row) | `cedant_workbook` |
   | `_LISTS`, `_META` (hidden) | Dropdown sources; builder version, source spec hash, cedant spec hash | — |

   Dropdowns: fixed registry values (`product_type`, `regulator`, `gender`, `marital`, `member_category`, dimension
   families, `benefit_code` from `registry/benefits.json`), Y/N, enumerations above; cross-references (band set,
   column set, sheet, block) through dynamic named ranges so only defined names can be picked. Yellow = input,
   grey = derived / read-only, as in the cedant workbook.
3. **Read-back gates** (stop with the cell list): blank mandatory cell; a value outside its dropdown list (pasted
   values bypass validation); duplicate sheet_name / block_id / component_id / band label within a set; a reference
   to an undefined band set, column set, sheet or block; a TPA twice on one sheet (§8.0); custom rows combined with
   bands or sections on one block; age from > to or overlapping bands in a set; a factor table without exactly one
   reference per key; an unknown benefit code; then the existing spec validator and `spec.cedant_model` on the
   result. Warnings (do not stop): a sheet with no blocks, a block with no plans, plan letters with gaps.
4. **Fields not carried** (`_note`, block `comment` aside, `source_flags`, `pending`, `cedant_workbook.provisional`
   / `decided`, any unknown key): listed on the Cover. `read_builder(..., base_spec=)` copies them from the base
   spec unchanged; without a base spec they are dropped and listed as warnings. Age bands are written inline
   (`age_band_sets`); with a base spec that used `age_bands_file`, the file reference and the file are kept and the
   read stops if the builder's bands differ from the file's (the file is then edited, not overwritten).
5. **Output JSON**: canonical key order (as `spec.py` normalises), row order from the builder, `indent=1`,
   UTF-8, LF, trailing newline. Same builder → byte-identical JSON.
6. **CLI**: `py tools\pw.py t spec-builder [<template_spec.json>] --out <builder.xlsx>` and
   `py tools\pw.py t spec-read <builder.xlsx> --out <template_spec.json> [--base <template_spec.json>]`
   (report `<out>_read_report.csv`; prints `SPEC READ PASS` / `SPEC READ FAIL`).
7. **Tender folder** (`pw/tender_kit.py`): step files `0a_make_spec_builder.bat` (pre-filled from
   `inputs\template_spec.json` when present, else blank, to `work\spec_builder.xlsx`) and `0b_read_spec_builder.bat`
   (reads `inputs\spec_builder.xlsx`, base = the current `inputs\template_spec.json`, writes it back only on PASS
   and keeps the previous one as `inputs\template_spec.previous.json`). README lines for both. The training tender
   gains a pre-filled builder from C_ALPHA.
8. **Guide**: `docs/spec_builder_guide.md` for non-technical users: what each sheet means, the five structured
   fields (formula, splits, sections, custom rows, refer cells) with the UFIC-shaped examples written in labels
   only, and the PASS / FAIL loop.
9. Release 0.0.7 (`pw.__version__`), docs/INSTALL.md, HANDOVER.md.

## Acceptance criteria
- **Round trip, every spec in the repo** (`fixtures/T_ALPHA`, `fixtures/C_ALPHA`, `examples/ufic_2027`):
  spec → `spec-builder` → `spec-read --base spec` gives a spec whose normalised form, `spec_hash` and cedant spec
  hash equal the original's, and from which `t generate` and `t cedant` write byte-identical workbooks.
- A builder filled from blank (in the test, by openpyxl, as a user would) reproduces `fixtures/C_ALPHA/template_spec.json`
  semantically (normalised equal) and passes V4.
- Every gate in deliverable 3 has a test that plants the fault and checks the cell named in the report.
- Byte-identical JSON on a second read; byte-identical builder on a second generate.
- The builder opens in Excel with working dropdowns (laptop check opens it) and holds no client values: the UFIC
  pre-filled builder is structure only, and no builder for UFIC is shipped in the release (boundary test).
- `tools/laptop_check.py` covers `t spec-builder`, `t spec-read` and the two new step files on the training
  tender (SPEC §13 coverage rule).
- Full suite green; laptop check PASS on the owner's laptop.
